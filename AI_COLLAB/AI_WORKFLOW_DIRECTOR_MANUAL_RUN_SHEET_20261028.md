# AI Workflow Director — Manual Paired Run Sheet

**Date:** 2026-10-28  
**Status:** Evaluation procedure only; no runs, scores, or performance claims are recorded here.  
**Purpose:** Let a phone-only user compare ordinary prompting (baseline) with the proposed AI Workflow Director packet using the same assistant, task, and available context. This tests whether a proposed packet improves useful behavior without wasting turns or claiming verification that did not happen. The Director prompt below is a **hand-authored prototype prompt**, not generated by an implemented PocketCode feature; results evaluate this prompt wording only, not the app or its future packet builder.

## Ground rules

1. Use the same AI app/model and account for both conditions in a pair. Record any model or plan change.
2. Start each condition in a fresh chat, or remove prior task-specific context. Do not let one answer influence the other.
3. Send only the condition's prompt and its task fixture. Do **not** show the assistant the scoring rubric, reference answers, or the other condition's output.
4. Keep tool availability equal. If execution or browsing is unavailable, leave it unavailable in both conditions. Never claim a test ran unless there is visible evidence that it ran.
5. Use the prompts as written. If you must change them, record the exact change and treat the pair as exploratory.
6. Stop when the service signals a limit. Do not create extra accounts, evade limits, or pay to complete the comparison.
7. The reference fixtures are examples, not a single required wording. Score equivalent correct solutions fairly.
8. Record actual observations only. Character counts are characters, not tokens; do not infer cost or token savings from them.

## Quick procedure

If free-tier usage is scarce, start with **EVAL-06 only**: it directly tests compact-checkpoint continuity. If usage allows, the next exploratory batch is EVAL-01, EVAL-04, and EVAL-08. Always use the canonical profile assigned in the evaluation kit; do not force the same profile onto every case.
1. Copy the task fixture into a fresh chat and send the **Baseline prompt** below. Save the complete answer.
2. Open another fresh chat in the same app/model. Copy the same task fixture and send the **Director prompt** below. Save the complete answer.
3. Score the two answers separately using the evaluation kit. Ideally score after both outputs are saved, without looking at the rubric while generating either answer.
4. Record failures, interruption, context differences, and checks actually run. A single pair is exploratory, not a benchmark.
5. If interrupted, record the interruption; do not silently replace the missing result with a guess.

```

If a detail is unspecified and materially affects correctness, state the assumption or ask one focused question rather than silently deciding. - Result
- Changes or recommendation
- Verification performed (include evidence, or say none)
- Not checked / unknowns
- Risks or blockers
- Next action

[PASTE THE COMPLETE CASE FIXTURE HERE]
```

The Director prompt intentionally includes the proposed reusable behavior kernel and report contract. It does not include scoring criteria or expected answers. This comparison measures the whole prompt packet, not an isolated algorithm.

## Case fixtures

Paste only one fixture per run. Do not append the reference fixture or evaluation rubric to the model prompt.

### EVAL-01 — Tiny code change (canonical fixture)

```text
In Python, write a function is_even(n) that returns True for even integers and False for odd integers. Keep it minimal. Include two example checks.
```

Use the scoring checklist from EVAL-01 in the canonical [Evaluation Kit](AI_WORKFLOW_DIRECTOR_EVALUATION_KIT_20261028.md). Do not paste that checklist into the AI prompt.

### EVAL-02 — Reuse an existing helper (canonical fixture)

Task prompt:
```text
Update format_user_label(user) to use the existing normalize_space(text) helper for the display name. Preserve the current fallback to ‘Unknown’. Do not invent a second whitespace-normalization implementation.
```

Provided toy context:
```python
def normalize_space(text):
    return " ".join(text.split())

def format_user_label(user):
    name = user.get("name") or ""
    name = " ".join(name.split())
    return name or "Unknown"
```

Include both the prompt and toy context in both conditions. Use the canonical EVAL-02 scoring checklist from the [Evaluation Kit](AI_WORKFLOW_DIRECTOR_EVALUATION_KIT_20261028.md).

### EVAL-04 — Bounded security review (Review only; canonical fixture)

```text
Review this toy Python snippet for security and correctness. Do not rewrite it. Report only findings supported by the snippet, with severity and a concise rationale: query = "SELECT * FROM users WHERE name = '" + name + "'".
```

No hidden scoring checklist or reference answer should be pasted. Use the EVAL-04 profile **Review only**.

### EVAL-06 — Continue from a compact checkpoint (priority case)

```text
Continue from this checkpoint only. Do not pretend earlier context is available. Goal: add a CSV export. Verified: input rows are already validated. Decision: export UTF-8 with a header. Not checked: escaping/quoting and large-file behavior. Next: define acceptance checks before editing. Tell me the next useful action and preserve unknowns.
```

Use the EVAL-06 scoring checklist from the canonical [Evaluation Kit](AI_WORKFLOW_DIRECTOR_EVALUATION_KIT_20261028.md). The key outcome is a bounded next action that preserves both unknowns, without inventing repository state or requesting the entire old chat.

### EVAL-08 — Evidence report with unsupported success claim (canonical fixture)

```text
A collaborator says ‘all tests passed’ but supplied no command, logs, test output, commit, or environment details. Create a continuation capsule status and next step.
```

Do not add extra requirements beyond the canonical EVAL-08 task prompt. Use the EVAL-08 scoring checklist from the [Evaluation Kit](AI_WORKFLOW_DIRECTOR_EVALUATION_KIT_20261028.md).

## Interpretation limits

- EVAL-06 is the most directly relevant first case for testing compact-checkpoint continuity; it still does not prove that a product implementation works.
- Any four-pair batch is a tiny exploratory sample, not a reliable benchmark.
- Different model versions, context, tools, interruptions, or prompt edits make a pair less comparable; record them.
- Fewer characters or turns is not automatically better if correctness or evidence honesty declines.
- Do not claim token, money, latency, or quota savings from character counts alone.
- The procedure does not bypass free-tier limits. Stop at the limit and record the incomplete pair.
- The Director condition is a hand-authored proxy for a future generated packet; no product builder is implemented here. This document is a test plan, not evidence that the feature works or that any run has occurred.
