## 2. Current name PocketCode / Pocket Code

VERIFIED: Catrobat's official developer portal describes Catrobat as a free/libre/open-source nonprofit project and says Pocket Code creates and executes programs on Android and iOS smartphones. Its official product documentation identifies Pocket Code as its main mobile app for creating games, animations and interactive stories on phones/tablets.

Sources:
- Catrobat developer portal: https://developer.catrobat.org/
- Official Pocket Code product explainer: https://catrobat.org/docs/getting-started/what-is-pocket-code/
- Catrobat apps page: https://catrobat.org/our-apps/

This is a direct same-category collision: PocketCode's current name is visually and verbally close to an established mobile coding app called Pocket Code. It creates user-confusion and search-discoverability risk. It does not, by itself, prove trademark infringement or establish who has priority in any jurisdiction.

## 3. Conclusion

- VERIFIED: the current PocketCode name overlaps directly with Catrobat's Pocket Code in the mobile coding category.
- VERIFIED: PoCo overlaps with the active POCO C++ Libraries developer ecosystem and its search footprint.
- UNKNOWN: whether Xiaomi's POCO trademark records cover the proposed software/service, their present legal status, or relevant countries/classes. The old aggregator claim must not be stated as a confirmed registration or legal risk.
- Proposed operating decision: do not rename the repository, documents or website yet; do not publish PoCo as the product name. Keep both names provisional until clearance.
- No App Store uniqueness rule or legal outcome is asserted here.

## 4. Clearance process

For any candidate name:
1. Search official Apple App Store and Google Play listings for exact and confusingly similar names in each target market.
2. Search GitHub repositories, packages, organisations, domain names and current commercial products.
3. Check exact and phonetic variants in official trademark databases for each intended market, including USPTO TSDR and EUIPO/TMview where relevant. Record owner, status, goods/services, classes, dates and territory from the authoritative record, not an aggregator.
4. Check domain and social-handle availability, recording the date because availability changes.
5. Prefer a distinctive coined name. Treat class and market overlap as a legal question for qualified review, not an automatic conclusion from Nice class numbers.
6. Record direct URLs, search date, exact search term and screenshot/export for any decision.
