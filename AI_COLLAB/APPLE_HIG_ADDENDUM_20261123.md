# APPLE HIG ADDENDUM for the PoCo web spec (strategy research question 2)

Written 2026-11-23 by Claude. Extends APPLE_DESIGN_ENGINEERING_SPEC_20261108.md, which read only the Materials and Motion pages. This pass read the Typography, Layout, Buttons, Sheets and Accessibility pages of Apple's Human Interface Guidelines (developer.apple.com/design/human-interface-guidelines/*, as search excerpts), plus App Store Connect Help pages on accessibility evaluation. Tags: VERIFIED (stated on an Apple page named here), MIRROR (a third-party copy of Apple's text), INFERRED, UNKNOWN. Excerpts are partial; a full read of each page may add detail. Status: PROPOSED; nothing is implemented.

## 1. What the pages say (VERIFIED unless marked)
- **Type size:** iOS and iPadOS default text size 17 pt, minimum 11 pt (Typography table; the same table is in a MIRROR, which also lists macOS 13 and 10). SF Pro is the iOS system font; New York is an optional serif. Thin custom weights call for larger sizes; avoid tight leading for three or more lines. At the smallest Dynamic Type setting a Large Title is 31 pt and Caption 2 is 11 pt (excerpt).
- **Enlarging text:** people should be able to enlarge text by at least 200 percent (Accessibility page, MIRROR text). App Store Connect Help says Dynamic Type on iOS passes 200 percent at the AX3 size and body text passes 300 percent at AX5, and that an in-app font control counts if it reaches equivalent sizes.
- **Touch targets:** controls must be at least 44 by 44 points (Layout page, Buttons page and Apple's design tips page). In iOS Safari one CSS pixel equals one point.
- **Layout:** respect system margins and safe areas; a full-width button at the bottom should align with the bottom of the safe area and clear the Home indicator; be ready for text-size changes; preview on several devices, orientations, languages and text sizes.
- **Buttons:** four styles in three sizes on iOS; use style, not size, to mark the preferred choice; give the primary role to the nondestructive button; too many filled buttons raise cognitive load.
- **Sheets:** use a sheet for simple content or a scoped task and consider full-screen presentation for long or complex flows; iOS sheets support the large detent by default and the medium detent is optional; include a grabber on a resizable sheet (it also works with VoiceOver and a tap cycles the detents); support swipe to dismiss; a sheet can be nonmodal on iOS; use an alert or action sheet for important information or simple choices.
- **Contrast:** text up to 17 pt needs 4.5:1 at any weight; 18 pt text needs 3:1; bold text of any size needs 3:1. If the default colours miss this, provide a higher-contrast scheme when Increase Contrast is on, and check both light and dark appearances. App Store Connect Help names the related settings Bold Text, Increase Contrast and Reduce Transparency.
- **Not colour alone:** state must also be conveyed by shape, icon, placement or text; Apple's test is to use the app in grayscale. Images and graphics need accessibility labels that include any text in them.
- **Reduce Motion:** apps should follow the HIG motion guidance and respect the user's Reduce Motion setting (Apple accessibility conformance reports).

## 2. Effect on the spec (INFERRED unless marked)
1. The spec's 44 by 44 point target moves from SECONDARY to VERIFIED. Its "8 to 12 point gaps" is still unsourced; I did not find it on these pages.
2. Contrast arithmetic on the spec's provisional tokens (WCAG formula, done by hand; recheck with a contrast tool before relying on it). On white: `--state-pass` #1f8a4c about 4.4:1, `--state-incomplete` #b26a00 about 4.2:1, `--accent` #0a84ff about 3.7:1; all three are below 4.5:1, so they are not safe for small text. `--state-fail` #c62828 (about 5.6:1), `--label-2` #5b5b63 (about 6.0:1 on #f2f2f7) and `--state-unknown` pass. In dark mode the state colours are not redefined, and #b26a00 on #1c1c1e is about 4.0:1. Fix: darker text variants for small state labels (or use the colour only on 18 pt or bold text, with the label itself in `--label`), and dark-mode state tokens.
3. Add an Increase Contrast branch: `@media (prefers-contrast: more)` with darker secondary text and stronger separators. Safari support of the query is UNKNOWN to me; verify on the iPhone, and keep the tokens passing 4.5:1 by default so the branch is a bonus.
4. Type: the ramp's smallest size (0.75rem, 12 px) is above the 11 pt minimum. The spec's body size is 1rem (16 px) while the iOS default is 17 pt; the spec's `html { font: -apple-system-body }` line should give 17 px at the default setting, so confirm that on the device and do not set a body size after it.
5. Sheets: the spec's bottom sheet should show a grabber, support swipe to dismiss and offer a close control; keep run details in a sheet only when the task is simple, and use a full-screen view for long logs or a multi-step flow.
6. Buttons: one primary action per screen, marked by style, with destructive actions never the primary role; keep every hit area at 44 by 44.
7. Test plan additions: use the app in grayscale; text at the largest accessibility size and at 200 percent; Reduce Motion, Reduce Transparency and Increase Contrast on; VoiceOver labels on every icon-only control.
