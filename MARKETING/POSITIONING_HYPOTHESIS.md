# Marketing and Positioning Hypothesis

**Status:** Working hypothesis, not a final brand or validated positioning  
**Last reviewed:** 2026-10-20

## Core recommendation

Use **vibe coding** as the discovery/marketing hook, **from your phone** as the accessibility promise, and **real execution evidence** as the product proof.

### Primary message to test

> **Vibe code. Run it. Fix it. From your phone.**

Supporting line:

> Bring AI-generated code to a phone-friendly workspace, run it in a supported environment, see what actually happened, and use the result to improve the next attempt.

This describes the intended workflow. It must not be presented as an existing capability until the execution path is built and verified.

## Why this direction

The phrase “vibe coding” is now widely used in AI-assisted app creation and has become a common discovery term. But “build apps with AI from your phone” is already a crowded promise. Products and guides currently cover mobile AI app creation, mobile IDEs, remote coding agents, and cloud workspaces. See the competitor research for the wider landscape.

A potentially narrower message is the loop after code generation:
1. Start with code from any AI assistant.
2. Run it in a clearly described supported environment.
3. See actual output and errors.
4. Share a structured execution report with the AI assistant of choice.
5. Apply a fix and rerun to check the result.

This is a differentiation hypothesis, not a verified unique selling point. Competitors may already support parts or all of this loop.

## Audience hypotheses

### Primary to interview first
People who use ChatGPT, Claude, Gemini, or another AI assistant to generate code, but do not always have a laptop/desktop available to test it.

### Secondary
- Beginners learning by asking AI to write or explain small scripts.
- Hobbyists who want to transform files or automate small tasks from a phone.
- Developers who need a lightweight way to reproduce a bug or verify a small code change away from their main computer.

Do not assume these audiences have the same needs. Test which group experiences the problem most frequently.

## Message hierarchy

1. **Hook:** Vibe code from your phone.
2. **Problem:** AI-generated code still needs to be run and checked.
3. **Product promise:** Test supported code, inspect real output/errors, and iterate from a phone.
4. **Trust signal:** Clear run status and actual execution results—not fabricated success states.
5. **Freedom:** Bring code from the AI assistant you already use; no mandatory AI-provider lock-in is part of the current product direction.

## Candidate headlines

- **Primary:** Vibe code. Run it. Fix it. From your phone.
- **Alternative:** Your AI wrote the code. Now test it—from your phone.
- **Utility-led:** Run and debug AI-generated code from your phone.
- **Beginner-led:** Turn AI-generated code into something you can actually test.
- **Short tagline:** Code beyond the laptop.

Do not claim “any language,” “runs everything,” “fully offline,” “no limits,” or “production-ready apps” unless a tested product actually supports the claim.

## Landing-page draft (for later, after the execution proof)

**Headline:** Vibe code. Run it. Fix it. From your phone.

**Subheading:** AI can write code anywhere. PocketCode is exploring a simple way to run supported code from your phone, inspect real results, and take the next fix back to your AI assistant.

**Three steps:**
1. Paste code and add the files it needs.
2. Run it and inspect output, errors, and generated files.
3. Share the execution report with your AI assistant, improve the code, and try again.

**CTA before the product exists:** Join the early-access research / Tell us what you want to run from your phone.

**CTA after a working prototype exists:** Try the Python run-and-check demo.

Keep the page explicit that the product is early-stage until the prototype is real. Do not collect email addresses until a privacy-conscious signup mechanism and retention policy are ready.

## Validation plan

Before committing to a final slogan or brand:
- Interview 5–8 people who have tried AI-generated code on a phone.
- Ask what they tried to build, where the workflow broke, what they used to run it, and whether they would use a separate tool.
- Compare the proposed headline against “Code from your phone” and “Test AI-generated code from your phone.”
- Measure whether people understand the product as a code runner/verification workspace rather than a prompt-to-app generator.
- Revisit this positioning after a real execution demo and competitor hands-on tests.

## Risks and caveats

- “Vibe coding” is a trend term and may age; keep the underlying product promise understandable without it.
- The market for mobile coding and AI app builders is crowded; marketing language alone is not differentiation.
- The product name PocketCode is provisional. A similarly named existing product creates naming and discoverability risk; do not invest in final branding before a fuller trademark/domain review.
- No product functionality should be advertised as live until it is implemented and verified.
- This document records a hypothesis, not customer validation or legal advice.
